# Journal: June 16-18, 2026 — Starting Nox

## What I was building

This is the earliest surviving record of the project, right before the first commit ("initial commit: autonomous quantitative trading system framework" on June 18). I was setting up the basic skeleton: a heartbeat/monitoring service that sends me a daily report over Telegram, and the analyst/execution split that everything else is built on.

## What broke, and how I found out

**The daily report kept getting cut off.** I noticed the morning report was truncated mid-sentence. My first fix was a token-limit bump — I'd set `max_tokens=4096` on the report-generation call, an order of magnitude under what the model actually supports, while at the same time telling it in the system prompt "do not truncate, complete every section fully." Those two instructions directly contradicted each other. I raised the limit once, and it happened again two days later — the report content had grown (more headlines, more filings) and the same fix undershot the real requirement a second time. I raised it further and asked myself the more useful question: was the report supposed to be that long in the first place, or was I generating bloat and then fighting the symptom? I didn't have a clean answer yet, which is honestly more useful to admit than pretending I'd nailed it in one pass.

**A webhook between two of my own services was silently rejecting requests.** The analyst container's POST to the execution container was coming back HTTP 400. I made an assumption early — that a Python component was the sender — and it was wrong; grepping the actual codebase showed both sides were C++. Once I stopped guessing and read the real client construction code, the bug was a one-line difference in how an HTTP client library builds its connection string for Docker-internal networking (host+port vs. a full URL). Fixed, rebuilt, and verified by watching both containers' logs actually show the request landing — not just that the diff compiled.

**A safety-rule test got left unfinished.** I was writing a test to confirm the engine fails loudly (rather than silently) when a required config value is missing, and got interrupted before actually running it. It sat half-written for a while. Not proud of that gap, but it's an honest one: a safety-critical rule's test existed in source but wasn't confirmed working for a stretch of time.

## What I'd tell someone about this period

Nothing here was solved in one clean shot. The recurring pattern — first fix addresses the symptom, second pass (sometimes days later) finds the actual root cause — shows up again and again through this project's history, and it starts right here. I'd rather show that pattern honestly than pretend the first attempt was always the right one.
