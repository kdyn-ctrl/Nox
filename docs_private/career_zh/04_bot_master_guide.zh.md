# 大师指南——让 Nox/Nocturnal 融入你的骨血

目标：读完这篇之后，你应该能够凭记忆、用自己的话解释这个系统的任何一部分，而不需要翻代码。全文按叙事方式组织，方便你复述，而不是当作参考手册来查阅。

## 一句话电梯演讲

"这是一套交易美国和中国股票/期权的系统。每一个信号在被信任之前，都必须先经受住独立数据源的反驳检验；风险控制被设置在执行层（而不仅仅是策略层）；整个系统能够从自身的故障中自我恢复，因为我已经被它悄无声息地失效坑过一次了。"

## 完整故事，按顺序讲（这也是你"带我过一遍系统"这个问题的标准答案）

**1. 数据从多个独立来源流入**，被拆分成两套引擎，因为美国和中国的市场结构差异大到值得分开处理（结算周期、信息披露规范、资本管制、交易时段/熔断机制——面试时至少要能说出两个你实际依赖的具体差异）。

**2. 每个信号在被信任之前都要经过交叉验证——这是核心设计哲学（Skeptic 架构）。**
- **矛盾向量（WS1）：** 文本情绪（基于词典打分，带方向和幅度）会与期权隐含波动率偏斜（IV skew）进行对照。如果两者一致 → CONFIRM（确认）。如果两者朝"有信息量"的方向出现分歧 → CONTRADICT_*（矛盾）。如果看涨的文本恰好碰上看跌但为正的偏斜，而这其实只是噪音 → IGNORE（忽略）（这个区分很关键——不是所有分歧都有信息量，有些只是偏斜本身的正常表现）。
- **另类宏观（WS2）：** 物理世界的压力信号（油轮航运偏离、海运保险费变化）对比政治/新闻信号，按地理咽喉要道分别处理（霍尔木兹海峡、红海、黑海、委内瑞拉）。当两者冲突时，以物理数据为准，因为物理流量比新闻标题更难造假或操纵舆论。
- **内部人集群过滤（WS3）：** 基于 SEC Form 4 申报，但只看公开市场买入（交易代码 "P"），明确排除 Rule 10b5-1（这类交易是预先排定的，不携带新信息）。要求在滚动 48 小时窗口内有 ≥2 位不同的高管/董事买入——是一个"集群"而不是单笔申报，因为单个内部人买入信号很弱、也容易被解释掉（比如分散配置、薪酬发放时点）；而 48 小时内的集群则很难用巧合来解释。

**3. 信号会衰减——没有什么是永远被信任的（WS4，基础层）。**
每个信号都属于某个 `SignalCategory`，并按各自的半衰期呈指数衰减（λ = ln2/半衰期——标准的放射性衰变式数学，与一级化学反应的形式相同，这对你来说是个很有用的心智模型）。在稳定衰减之上，还可能触发**机制重置（regime reset）**——通过 VIX 跳升检测触发（`detect_volatility_catalyst`）——这是一个"一次性消耗锁存器"：每次催化事件只触发一次，强制将信号视为过期，且在重置之前不会再次触发。这个机制的存在是因为市场机制变化（比如一次冲击）会让冲击前的信号变得具有主动误导性，而不仅仅是"过时"而已。

**4. 宏观/周末层运行在独立的节奏上（WS6）。**
一个周六早上的定时任务（`weekend_batch.sh`）直接运行 WS1-3 的流程（不走 HTTP 往返，而是进程内直接调用 Python 函数），产出一份评分报告（每个工作流分为 HIGH/MEDIUM/LOW 三档信心等级），同时输出 JSON 和 Markdown 两种格式，因为周度/周末研究不需要实时服务的低延迟，做成批处理更简单也更省成本。

**5. 在任何信号触达订单之前，都要先通过流动性关卡（WS5）。**
`LiquidityGate` 跟踪每个标的滚动的相对买卖价差基线，并计算 z 分数；如果当前价差超过若干个标准差（说明流动性稀薄或承压），就会中止该笔交易。有两个重要的设计取舍需要能够辩护：
- **数据缺失/异常时选择"放行"（fail-open）**——如果该关卡无法计算出价差，它会放行交易而不是阻止它。理由是：一个损坏的数据源不应该有能力悄无声息地叫停全部交易（那本身就是一种风险），所以这里的权衡是"偶尔在没有这层保护的情况下交易" vs "一次数据故障拖垮整条执行链路"。
- **预热期**——在积累到足够的历史数据、形成真正的基线之前，该关卡不会生效，避免冷启动时出现误判中止。
- 在执行顺序中被放在**名义金额上限检查之后**——先检查仓位大小（一个便宜的静态检查），再在交易真正触发前检查市场质量（一个更昂贵的实时检查）——遵循"先做最便宜、最确定的过滤"原则。

**6. 持仓一旦建立，会通过一套真正的账本进行跟踪，并配合基于规则的离场机制。**
这套机制源于修复一个真实的 bug：`add_position` 是从未被调用的死代码，导致期权持仓实际上从未被真正卖出——发现并修复了这个问题，同时构建了作为正式账本的 `trade_history`、带对账功能的权益持久化（纸上交易 vs 实盘），以及基于规则的权益离场机制。在账本之上还构建了报告（EOD/EOW，即日终/周终报告）和一个 `/trades` 接口，让绩效可以被直接查验，而不只是从日志中推断。

**7. 数据可靠性是刻意为之的防御性设计，是吃过亏才学到的。**
所有 SEC/新闻/API 的抓取都带有重试/退避机制。报告在数据不完整时**拒绝生成**——建立在部分数据上的报告比没有报告更糟糕，因为它看起来权威却是错的。这与之前的一次事故（见下文）形成呼应——系统现在选择"大声失败/拒绝执行"，而不是"悄无声息地失效"。

**8. 塑造了当前日志架构的那次事故。**
2026年6月28日，容器悄无声息地崩溃，analyst→execution 之间的通信中断，且在相当长一段时间内无人察觉。修复方式是在整个 docker-compose 技术栈中为 analyst 和 execution 两个容器都增加了持久化日志，并验证了 analyst-execution 通信已恢复（于2026年7月1日完成）。这是你回答"讲讲一次生产环境故障"这类问题时最好的素材——要记住具体细节：哪些容器、"悄无声息"具体指什么（没有崩溃日志、没有告警，只是停止产生输出）、日志改动现在具体捕获了什么、如果今天再次发生你要如何得知。

**9. 公开版与私有版的拆分。**
`main`（Nox，公开的 GitHub 仓库）包含架构中公开安全的子集；`nocturnal`（私有仓库）保存真正的优势所在——例如多源新闻回退管道（Alpaca→NewsAPI→Polygon→RSS）只存在于 `nocturnal` 上。这个拆分本身就是一个可以谈的点：你理解知识产权/优势保护的重要性，而不是"什么都要开源"，这在任何真正的交易机构里都是一个现实的考量。

## 需要能在白板上推导出来、而不只是背诵的内容
- 指数衰减公式，以及为什么 λ=ln2/半衰期能保证在 t=半衰期时刻恰好衰减到一半（基本推导：N(t)=N0·e^(-λt)，令 N(半衰期)=N0/2 求解即可）。
- 为什么 z 分数是判断"这个价差是否异常"的正确工具（假设价差在局部窗口内近似服从平稳分布；z 分数 = (当前值 - 均值)/滚动窗口内的标准差）。
- 从信号 → 矛盾检验 → 衰减/机制检验 → 仓位规模计算 → 流动性关卡 → 下单 → 账本更新的完整操作顺序。如果被要求凭记忆把这个画成流程图，你应该能画出来。

## 需要坦诚承认的不足之处（不要假装它们不存在）
- 目前还没有带有真实成本假设的样本外回测数据——参见 [[02_quant_evaluation_criteria]]。
- 跨工作流的融合逻辑是基于规则的，而不是学习/加权得到的——你有一套合理的辩护理由（可解释性、数据稀缺），但目前还没有实证对比。
- 情绪打分是基于词典的，而不是语言模型——这是一个刻意的选择（容器内不想承载繁重的 NLP 权重，受内存限制），但要诚实面对这种做法所隐含的准确率上限。

在任何面试前，把这份文件从头到尾再读一遍，然后逐节大声、脱稿地重新推导一遍——这才是检验"它是否已经融入你骨血"的真正标准。
