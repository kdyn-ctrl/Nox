================================================================================
核心原则
================================================================================

“每一次代码变更都必须在同一次提交中包含相应的文档更新。”

这样可以保持文档与代码同步，防止指南逐渐过时失效。

================================================================================
快速入门
================================================================================

面向非技术用户：
  1. 阅读 NOX_USER_GUIDE.md
  2. 监控 Telegram 提醒
  3. 查看 Alpaca 仪表盘

面向开发者：
  1. 运行 ./run_tests.sh
  2. 提交前：查阅 TEST_UPDATE_CHECKLIST.md
  3. 在同一次提交中更新受影响的指南
  4. 复制粘贴一个示例并验证其可用性
  5. 将代码与文档一起提交

面向维护工作：
  1. 每月：随机挑选一份指南，运行一项测试
  2. 每季度：检查所有“最后验证时间”戳记
  3. 发现漏洞时：向指南中添加相应测试用例
  4. 代码变更时：立即更新相关指南

❌ 向后兼容性（由一人独立维护）

================================================================================
维护计划
================================================================================

每月（30 分钟）：随机抽查一份指南
每季度（1 小时）：检查“最后验证”日期，更新过期内容
发现漏洞时：立即向指南添加测试用例
代码变更时：提交前先更新指南

需要更新指南的警示信号：
- 示例代码无法编译通过
- 实际输出与预期输出不符
- 指南中的阈值与代码中的阈值不一致
- 指南中提到的环境变量在代码中不存在
- 实际提醒消息与指南描述不符

================================================================================
如何使用本文档系统
================================================================================

开发新功能时：
  1. 进行代码修改
  2. 使用 TEST_UPDATE_CHECKLIST.md 查找需要更新的指南
  3. 更新这些指南
  4. 复制粘贴一个示例并验证
  5. 将代码与指南一起提交

代码审查时：
  1. 检查是否遵循了 TEST_UPDATE_CHECKLIST.md
  2. 对每份已更新的指南运行一个示例
  3. 验证阈值/参数值是否与代码一致
  4. 若文档与代码一致，则予以批准

日常维护：
  1. 执行每月抽查
  2. 如发现问题，立即修复
  3. 验证后更新时间戳
  4. 防止指南内容过时失效
