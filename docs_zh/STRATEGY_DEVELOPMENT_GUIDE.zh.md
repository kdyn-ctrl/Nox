# Nox — 策略开发与运维指南（新手版）

> **本文档面向对象：** 你，Nox 的操作者/开发者，当你想把 *"我有一个交易点子"*
> 变成 *"它已经在运行并被监控"*，同时不想爆仓、也不想被糟糕的统计方法自欺欺人时。
>
> 这是公开文档 `NOX_USER_GUIDE.md`（讲解日常操作机器人）和
> `PRIVATE_ROADMAP.md`（未来开发方向）的**私有**配套文档。也请阅读那两份文档——本文档聚焦于构建策略的*方法*，以及驾驭你所构建系统的*操作机制*。

---

## 第 0 部分 — 最重要的一条规则

**不要把真金白银押在一个尚未经过 (1) 样本外回测、(2) 统计显著性检验、
(3) 模拟盘验证的策略上。**

几乎所有新手的错误都是跳过这三步中某一步的变体。本指南接下来的大部分内容，
都是在讲*如何*在这套系统上完成这三件事。

## 第 1 部分 — 写策略之前你需要了解的概念

你不需要金融学位，但需要理解这八个概念。每个概念都附带一句"它在 Nox 里为什么重要"。

| 概念 | 通俗含义 | 在 Nox 中为什么重要 |
|---|---|---|
| **边际优势/期望值 (Edge / expectancy)** | 在多笔交易中，你平均每笔交易预期能赚多少钱 | 如果期望值 ≤ 0，任何风险管理都救不了你。Kelly 仓位算法在优势非正时会*直接停止*（RULE-005）。 |
| **胜率 (W)** | 盈利交易占比 | 输入 Kelly 公式：`KELLY_WIN_RATE`。 |
| **盈亏比 (R)** | 平均盈利大小 ÷ 平均亏损大小 | 输入 Kelly 公式：`KELLY_WIN_LOSS_RATIO`。 |
| **Kelly 仓位比例** | 为实现长期最优增长应该拿出多少比例的资金去冒险 | 引擎使用**分数 Kelly**（`KELLY_FRACTION`，默认 0.15），并设有 10% 的上限。满额 Kelly 太激进——见第 4 部分。 |
| **回撤 (Drawdown)** | 权益从峰值到谷底的下跌幅度 | 这是让你想放弃的数字。50% 的回撤需要 100% 的涨幅才能回本。 |
| **过拟合 (Overfitting / curve-fitting)** | 不断调整规则，直到它在*历史数据*上看起来完美 | 这是回测结果骗人的头号原因。要靠样本外测试 + MCPT 来破解。 |
| **前视偏差 (Look-ahead bias)** | 使用策略在当时本不可能知道的信息 | 本项目的回测引擎都是按"严格无前视"（只使用 `bars[0..end_idx]`）原则编写的。修改回测器时务必保持这一点。 |
| **市场状态 (Regime)** | 当前市场是风险偏好开启还是关闭 | Nox 通过 `RegimeStateMachine` 用 VIX + SPY-200 日均线来控制入场。忽略市场状态的策略会一头扎进崩盘行情里。 |

### 期权相关概念（仅在交易期权时需要）

- **希腊字母 (The Greeks)** — Delta（方向性敞口）、Theta（时间价值衰减，卖方的朋友/
  买方的敌人）、Vega（波动率敞口）、Gamma（Delta 变化的速度）。Nox 通过
  Black-Scholes 模型（`OptionEngine.hpp`）计算全部五个希腊字母。
- **隐含波动率 vs 历史已实现波动率 (IV vs HRV)** — *隐含*波动率（期权价格所预示的）
  与*历史已实现*波动率（股票实际发生的波动）的对比。Nox 的核心期权优势在于
  **波动率风险溢价**：当 `IV > HRV × 1.20` 时，期权"偏贵"→ 倾向于*卖出*权利金
  （现金担保卖出看跌/备兑卖出看涨/宽跨式空头）。当 `IV < HRV × 0.90` 时，"便宜"
  → *买入*权利金（买入看涨/看跌/跨式多头）。
- **DTE** — 距到期天数。DTE 越短，Theta 衰减越快，但 Gamma 风险也越高。
- **Nox 掌握的 8 种策略：** LONG_CALL（买入看涨）、LONG_PUT（买入看跌）、
  CSP（现金担保卖出看跌）、CC（备兑卖出看涨）、BULL_CALL_SPREAD（牛市看涨价差）、
  BEAR_PUT_SPREAD（熊市看跌价差）、STRADDLE（跨式）、STRANGLE（宽跨式）——
  由 `selectStrategy()` 根据方向性偏好 × 波动率状态来选择。

## 第 2 部分 — 策略开发生命周期

把它想象成一个漏斗。大多数点子都应该在第 2–4 步*夭折*，这才是重点。

```
1. 提出假设        →  "在 RISK_ON 状态下卖出超卖大盘股的看跌期权具有优势"
2. 明确规则        →  精确的入场/出场/仓位规则，不容含糊
3. 回测            →  使用 nox_backtest / backtest-engine 在历史数据上测试
4. 验证            →  样本外测试 + MCPT 显著性检验 + 滚动前向测试
5. 风险定仓        →  设置 Kelly 参数 / 风险档位 / 市场状态门槛
6. 模拟盘交易      →  在 Alpaca 模拟账户上运行，观察 2–4 周
7. 小仓位实盘      →  以有意义的最小仓位开始，逐步放大
8. 监控与复盘      →  Telegram 提醒 + 定期绩效复盘
```

### 第 1 步 — 提出假设
用一句可证伪的话写出来：*"当[某条件]成立时，[某标的]往往会
[某种表现]，我可以用[某策略]来捕捉它。"* 如果你无法精确地描述这个条件，
你就无法把它编码或测试出来。

### 第 2 步 — 制定毫无歧义的规则
一个策略 = **入场规则 + 出场规则 + 仓位大小**。例如：
- *入场：* 偏向看涨（价格 > SMA20 > SMA50，RSI 40–65）**且**市场状态 = RISK_ON。
- *出场：* 达到最大盈利的 +50%，或止损于 2 倍权利金成本，或剩余 21 天到期，
  三者以最先触发为准。
- *仓位：* 经市场状态调整后权益的 1%（风险档位 1）。

这些规则可以直接映射到代码中已有的参数开关——你很少需要发明新逻辑，
只需要调整参数。

### 第 3 步 — 回测（命令见第 3 部分）
运行它。关注：交易笔数、胜率、平均盈亏、总盈亏、最大回撤。
**对过于漂亮的结果保持怀疑**，尤其是交易笔数很少的情况。

### 第 4 步 — 验证（新手最容易跳过的一步）
- **样本外测试 (OOS)：** 在一段时间（例如 2015–2021）上开发/调参，然后在你
  从未看过的时间段（例如 2022–2025）上*只测一次*。如果样本外表现崩了，
  说明之前是过拟合。
- **统计显著性 (MCPT)：** 一个策略也可能只是运气好看起来不错。蒙特卡洛置换检验
  （`src/utils/mcpt/`）会把你的收益序列多次打乱，问："随机排列会不会也能
  产生这么好的结果？" **p 值 < 0.05** 意味着大概率不是运气。*重要提示：*
  MCPT 只对**路径依赖型**统计量有效（如最大回撤、权益曲线相关指标）——
  对均值/夏普比率无效，因为这些指标在打乱顺序后是不变的。项目自带的示例
  之所以使用最大回撤，正是出于这个原因。
- **滚动前向测试（进阶）：** 在一个滚动窗口上重新优化参数，然后在下一个窗口上
  测试，如此反复。这是最接近"如果实盘运行会怎样"的方法。
- **样本量：** 少于 30 笔交易 → 不要相信这个结果。"3 笔交易 100% 胜率"就是
  噪音（路线图里就真实记录过 `BEAR_PUT_SPREAD` 犯了这个错误）。

### 第 5 步 — 风险定仓（见第 4 部分）。
### 第 6 步 — 模拟盘交易

## 第 3 部分 — 使用回测器

系统提供**两个**回测器。根据你的策略类型选择对应的那个。

### A) 期权策略回测器 — `nox_backtest`
在 Yahoo OHLCV 数据上重演实盘 `OptionsSignalGenerator` 的逻辑，并用
Black-Scholes 模型重新定价。

```bash
cd /root/Nox/execution
# 编译（引擎需要 PositionManager.cpp + sqlite3；回测器本身更轻量）
g++ -std=c++17 -O2 -DCPPHTTPLIB_OPENSSL_SUPPORT -I. \
    -o nox_backtest backtest_main.cpp -lssl -lcrypto -lpthread

# 运行 — 所有参数均为 key=value 形式
./nox_backtest watchlist=SPY,QQQ,AAPL range=2y capital=50000
./nox_backtest watchlist=NVDA range=5y scan=5 profit=0.50 stop=2.0 profile=personal
./nox_backtest --help        # 查看完整参数列表
```
关键参数：`watchlist`（观察列表）、`range`（1y/2y/5y，回测区间）、
`scan`（每隔 N 个交易日扫描一次，必须 ≥1）、`profit`（止盈比例）、
`stop`（止损倍数，以权利金成本为基准）、`capital`（决定档位门槛）、
`profile=personal`（激进型配置）。

### B) 股票/市场状态回测器 — `backtest-engine`
用于使用市场状态机 + Kelly 公式的方向性 SPY 类策略。

```bash
cd /root/Nox/backtest-engine
g++ -std=c++17 -O2 -o backtester main.cpp
./backtester    # 读取数据 CSV；写出 trades.csv
```
先用 `scripts/download_data.py` 更新其数据（SPY + VIX 历史数据）。

### C) 统计显著性检验 — MCPT
```bash
cd /root/Nox
g++ -std=c++17 -pthread -o build/mcpt_main src/utils/mcpt/main.cpp src/utils/mcpt/mcpt.cpp
./build/mcpt_main
```
把你策略的逐笔收益输入进去，读取 p 值。

> **回测已经教给我们的一个诚实结论（路线图中已记录）：** 在使用固定隐含波动率
> 代理值的情况下，波动率溢价信号根本不会触发，SPY 跨式策略表现不佳，因为
> 已实现波动率始终低于隐含波动率。要完全信任收益型策略，需要真实的期权数据
> （付费数据源）。目前的期权回测结果应被视为*方向性的合理性检查*，而非金科玉律。

## 第 4 部分 — 仓位管理与风险控制（让你活下去的部分）

Nox 有三种仓位定量方式，由信号中的 `risk_tier` 字段决定：

- **档位 1（"标准"）** — 冒经市场状态调整后权益的 **1%** 风险，2.0 倍 ATR 止损。
- **档位 3（"接飞刀"）** — 冒 **5%** 风险，3.5 倍 ATR 止损。激进型。
- **档位 0 / 其他任何值** — 使用 **Kelly 公式**定仓。

### 通俗解释 Kelly 公式
Kelly 公式认为，实现增长最优的风险比例是 `K = W − (1−W)/R`。用 Nox 样本外
测试中表现最好的参数（W≈0.68，R≈2.32）计算，原始 Kelly 值约为 55%——
*极度*激进。因此 Nox 做了以下处理：
1. 乘以 `KELLY_FRACTION`（默认 **0.15**）→ 约 8.2%。
2. 硬性上限设为权益的 **10%**（RULE-005）。
3. 如果 Kelly 值 ≤ 0（没有优势）或者连一股都买不起，**直接停止该笔交易**——
   而不是悄悄退化成一个象征性的小仓位。

**新手建议：** 一开始把 `KELLY_FRACTION` 设得比你想象的*更低*（0.10–0.15）。
分数 Kelly 能大幅降低回撤，而对增长速度的影响很小。满额 Kelly 会带来
令人肠胃翻腾的剧烈波动。

### 无论你用什么策略都会生效的硬性安全门槛
- **市场状态门槛** — VIX ≥ 30 或 SPY < 200 日均线 ⇒ 新入场被阻止（资金
  乘数归零）。
- **RSI 下限** — RSI 低于 30 时禁止股票买入。
- **名义价值上限** — 订单金额不能超过权益的 10%（用于捕捉从定仓到下单之间
  发生的价格剧烈波动）。
- **A 股相关规则** — 100 股一手的取整规则，以及 A 股 T+1（当日买入不可
  当日卖出）限制。
- **财报门槛** — 期权扫描会跳过 5 天内即将发布财报的标的。

这些保护你都是免费获得的。开发新策略大多数时候只是在选择*参数*，
而不是移除安全保护。

## 第 5 部分 — 系统运维

### 5.1 各组件（正在运行的服务）
| 服务 | 端口 | 角色 |
|---|---|---|
| `execution-engine`（`nox_engine`） | 8080 | 通过 `/webhook` 接收信号，定仓并把订单路由到 Alpaca，同时运行两个期权扫描器和仓位监控器。 |
| `analyst-brain`（`analyst_agent`） | — | 每隔 `ANALYST_CYCLE_HOURS` 小时，抓取 VIX+SPY 数据，评估市场状态，向引擎发送一份 REPORT 审计信息。 |
| `america-data-engine` | 8001 | Alpaca 新闻 + 财报日历（FastAPI）。 |
| `china-data-engine` | 8000 | 东方财富热门板块、PMI、LPR、财联社新闻（akshare）。 |
| `heartbeat/monitor.py` | — | Telegram 机器人：状态查询、SEC EDGAR 备案雷达、隐含波动率百分位、持仓查询。 |

### 5.2 配置（`.env`）
引擎强制要求的变量（缺失任一都会直接中止启动）：
`ALPACA_API_KEY`、`ALPACA_SECRET_KEY`、`ALPACA_BASE_URL`（模拟盘还是实盘！）、
`WEBHOOK_SECRET_TOKEN`、`KELLY_WIN_RATE`、`KELLY_WIN_LOSS_RATIO`、`KELLY_FRACTION`、
`TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID`。
可选变量：`OPTIONS_BOT_*` / `OPTIONS_PERSONAL_*`（观察列表、扫描间隔、
是否自动下单、合约数量）、`CN_BOARD_LOT_SIZE`、`CN_POSITIONS_PATH`、
`ANALYST_CYCLE_HOURS`。

> **最重要的一个开关：** `ALPACA_BASE_URL`。
> `paper-api.alpaca.markets` = 虚拟资金。`api.alpaca.markets` = **真实资金**。
> 每次修改前都要反复确认。

### 5.3 构建与运行
```bash
# 编译实盘引擎（注意：需要 PositionManager.cpp 和 -lsqlite3）
cd /root/Nox/execution
g++ -std=c++17 -O2 -DCPPHTTPLIB_OPENSSL_SUPPORT -I. \
    -o nox_engine main.cpp PositionManager.cpp \
    -lssl -lcrypto -lpthread -lsqlite3

# 启动整套系统
cd /root/Nox
docker-compose up -d          # 启动所有服务
docker-compose ps             # 检查健康状态
docker-compose logs -f execution-engine   # 查看实时日志
docker-compose down           # 停止所有服务
```

### 5.4 手动发送信号（webhook 接口约定）
引擎监听 `POST /webhook`。信号为 JSON 格式（单个对象或数组）：
```json
{
  "secret_key": "<WEBHOOK_SECRET_TOKEN>",
  "ticker": "AAPL",
  "action": "BUY",                 // BUY | SELL | HOLD | REPORT
  "price": 195.50,
  "rsi": 48.0,
  "atr": 3.2,
  "risk_tier": 1,                  // 0/空=Kelly，1=1%，3=5%
  "stop_loss_atr_multiplier": 2.0,
  "vix": 18.0,
  "spy_price": 530.0,
  "spy_200_sma": 510.0,
  "trade_date": "2026-06-26"       // 可选；供回测器/T+1 判断使用
}
```
说明：
- **`secret_key` 错误会被静默丢弃**（返回 200，日志记录一条 WARN）——
  这是刻意设计，以防止攻击者探测认证边界。如果你的信号看起来被忽略了，
  先检查 secret 是否正确。
- `action: "REPORT"` 是一种审计心跳信号（分析代理会用到）；它会忽略
  价格/仓位相关字段。
- 期权扫描器按照自己的定时器运行——你不需要主动推送信号；它们会自己
  发出提醒（并可选择自动下单）。

### 5.5 机器人档位 vs 个人档位
- **BOT（机器人）** — 保守型；强制执行档位门槛与市场状态门槛；如果启用了
  `OPTIONS_BOT_AUTO_EXECUTE`，可以自动下单。
- **PERSONAL（个人）** — 激进型；所有策略均开放；**始终仅作参考**（永不
  自动下单）——它只会通过 Telegram 发送信号供你手动操作。

一开始请把自动下单**关闭**。观察这些参考信号数周。只有在你信任它们、
并且已经完成模拟盘验证之后，才启用自动下单。

## 第 6 部分 — 监控与复盘

- **Telegram 就是你的仪表盘。** 绿色 = 正常，黄色 = 需注意/触发门槛，
  红色 = 出问题（完整的提醒分类见 `NOX_USER_GUIDE.md`）。给机器人发送
  状态查询命令即可获得健康状况快照。
- **Alpaca 仪表盘** — 持仓/成交的最终依据。定期与 Telegram 的信息做核对。
- **复盘频率：** 每周检查一次实际胜率与回测胜率的对比。出现偏离，
  说明优势正在衰减，或者市场状态发生了变化。
- **仓位监控器：** 引擎中的 `PositionManager` 线程会自动对它记录的
  *单腿*期权持仓应用止盈目标/止损/21 天到期出场规则。多腿组合持仓
  **目前尚未**被自动管理（你会看到一条 WARN 提示）——目前需要手动管理
  这些持仓（详见路线图）。

## 第 7 部分 — 新手常犯的陷阱（务必牢记）

1. **过拟合** — 如果你调了 6 个参数直到曲线看起来很完美，那它其实是
   拟合了噪音。参数越少越好，并且一定要检查样本外表现。
2. **样本太小** — 一个策略需要几十笔交易之后，它的统计数据才有意义。
3. **忽视交易成本** — 佣金、滑点，以及买卖价差（尤其是期权），会
   蚕食掉本就微薄的优势。
4. **逆市场状态交易** — 各种门槛是用来保护你的；不要为了"抄底反弹"
   而关闭它们。
5. **跳过模拟盘直接实盘** — 永远不要这样做。永远先模拟盘。
6. **把运气误认为实力** — 运行 MCPT。一条好看的权益曲线，如果 p=0.4，
   那也只是一次抛硬币而已。
7. **`.env` 里忘了把实盘 URL 改回去** — 每次运行前都要确认
   `ALPACA_BASE_URL`。
8. **引入前视偏差** — 修改回测器时，只能读取到当前索引为止的 K 线数据。

## 第 8 部分 — 一个具体的第一个项目（照着做）

1. 选一个流动性好的标的（SPY）。
2. 提出假设：*"当偏向看涨且隐含波动率便宜（IV < HRV×0.9）时，买入看涨期权
   在 RISK_ON 状态下具有正的期望收益。"*
3. `./nox_backtest watchlist=SPY range=5y` — 查看交易记录、胜率、回撤。
4. 拆分数据：用 2018–2022 年的数据做观察，把 2023–2025 年留作样本外测试。
   它能挺过样本外测试吗？
5. 对收益序列运行 MCPT。p 值是否 < 0.05？
6. 如果它挺过了以上检验：设置 `risk_tier=1`，切到模拟盘，观察参考信号
   2–4 周。
7. 到那时候才考虑开启自动下单/实盘，且以最小仓位开始。

如果它在第 4 步或第 5 步就"死"了——**这是好事**。你刚刚省下了真金白银。
去尝试下一个点子吧。
